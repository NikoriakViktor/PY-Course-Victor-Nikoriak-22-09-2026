Проєкт taxi_delivery_redis

Архітектура: шість процесів, два сховища

«Смачно + Таксі» — не одна програма, а шість окремих процесів з docker-compose.yml. Вони не викликають одне одного напряму: спілкуються через Redis (черга, спільний стан, події), а правду пишуть у PostgreSQL. Натисни на сервіс або сховище — побачиш, що він робить, що читає й пише та як подивитися його лог.

🔮 Прогноз: генератор створив замовлення. Як диспетчер про нього дізнається, якщо генератор не знає навіть адреси диспетчера?

Через Redis: генератор робить XADD orders:new, а диспетчер чекає на цьому стрімі (XREADGROUP … BLOCK 1000). Вони знають лише назву черги. Тому диспетчерів можна запустити два, перезапустити чи на хвилину вимкнути — генератор цього навіть не помітить.

Натисни на блок схеми

Запуск і адреси

cd module_3/lessons/taxi_delivery_redis
docker compose up --build

дашборд        http://localhost:8060
API (Swagger)  http://localhost:8100/docs
Redis          redis-cli -p 6390
PostgreSQL     psql postgresql://taxi:taxi@localhost:5434/smachno

Подивитись усе наживо (другий термінал, та сама папка)

docker compose logs -f dispatcher simulator generator api
docker compose logs -f redis-monitor     # кожна команда Redis + хто її надіслав
docker compose logs -f postgres          # кожен SQL-запит + хто його виконав

Теги в логах: TASK — крок процесу, QUEUE — черга, REDIS — інші команди, PG — PostgreSQL, EVENT — подія, WARN — проблема.

Одне замовлення наскрізь: схема + справжні логи

Те саме замовлення, що й на вкладці «Життя замовлення», але очима сервісів. На схемі підсвічуються процес і зв'язок, що працюють зараз. Під нею — рядки логів, саме такі, які ти побачиш у docker compose logs. Цей екран можна показувати поруч із запущеним проєктом.


  

  







  
Чому так, а не інакше

  
Кожне рішення в проєкті відповідає на конкретну проблему. Тут зібрано питання, які студенти ставлять найчастіше. Відповідь завжди має форму «що обрали → яка альтернатива → чому не вона».

  

  







  
Шпаргалка: функція → команди → ключі

  
Уся «карта методів» проєкту в одній таблиці: який сервіс, яка функція Python, які команди Redis чи SQL вона надсилає, яких ключів або таблиць торкається і навіщо. Шукай за ключем (couriers:free), командою (SREM) чи сервісом.
