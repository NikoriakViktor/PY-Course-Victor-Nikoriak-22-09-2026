Почни звідси

Три бази — три ролі

У «Смачно + Таксі» дані живуть у трьох місцях, і в кожного своя робота. PostgreSQL пам'ятає назавжди. Redis тримає те, що потрібно «зараз»: де кур'єр, хто вільний, що в черзі. DuckDB відповідає на великі питання до всієї історії. Не «яка база краща», а «яка робота в цих даних».

🔮 Прогноз: чому б не тримати все в одному PostgreSQL? Що з ним станеться, якщо 8 кур'єрів щосекунди оновлюють координати, а дашборд щосекунди питає «хто де»?

Працюватиме, але кожне оновлення — це запис на диск, журнал WAL і нова версія рядка (MVCC). Нам потрібна лише остання точка, а історія координат нікому не потрібна. Redis тримає її в пам'яті й оновлює за мікросекунди. Зате для завершеного замовлення з грошима потрібна саме надійність PostgreSQL.

Натисни на базу

Як дані рухаються

  клієнт ──замовлення──▶  ⚡ Redis  ◀──щосекунди──  кур'єри (GEO)
                           │  черга, «хто вільний», кеш, лічильники
              доставлено ──┘
                           ▼
                      🐘 PostgreSQL   (джерело правди: довідники + історія)
                           │  вивантаження раз на добу / тиждень
                           ▼
                      🦆 DuckDB + parquet   (аналітика: «виторг по районах за рік»)

Redis і PostgreSQL працюють разом, а не замість одне одного. Redis прискорює й координує. PostgreSQL пам'ятає. DuckDB аналізує те, що PostgreSQL накопичив.

Правило вибору: три питання

  1. Чи можна це втратити? Ні (гроші, довідники, завершені замовлення) → PostgreSQL
  2. Потрібно «зараз» і дуже швидко? Живе секунди чи хвилини, або кілька сервісів мають домовитися (черга, захоплення, лічильник) → Redis. Якщо це копія, правда однаково лежить у PostgreSQL.
  3. Питання до всієї історії? Суми, середні, тренди по мільйонах рядків → DuckDB над вивантаженою історією.

Тренажер: куди покласти ці дані?

Для кожного шматка даних «Смачно + Таксі» обери базу за трьома питаннями з попередньої сторінки. Після відповіді побачиш, де саме ці дані лежать у проєкті: ключ Redis або таблицю PostgreSQL.

Правильно: 0 з 0

Часто відповідь — «обидві»: правда в PostgreSQL, швидка копія в Redis. Так влаштовані меню (menu_items → cache:menu:<id>) і ресторани (restaurants → restaurant:<id> + restaurants:geo).
